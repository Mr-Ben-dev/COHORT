# What COHORT does NOT claim

Honest boundaries for judges, patients, and trial sites. These are deliberate
non-claims, pinned by `TESTS/non-claims.test.mjs` so no future edit can
quietly add hype.

## 1. COHORT is not HIPAA-compliant, and it is not a medical certification

A proof attests that a computation was run correctly over committed
attributes — it does **not** say the underlying attributes are medically
true. COHORT proves *what the computation says*, not *what is true about
your health*. Nothing here is a HIPAA compliance claim, and nothing is a
medical certification of eligibility.

## 2. The demo issuer is not a hospital

The "issuer" in this demo is a **DEMO issuer** — a throwaway key generated by
`scripts/issuer-ceremony.mjs`. It is not a hospital, not a medical
authority, and not a real-world trusted party. Any attestation signed by it
carries demo weight only.

## 3. Wave-1 eligibility facts are self-asserted by the patient

In Wave 1, the eligibility attributes the patient proves over are
**self-asserted**: the patient supplies them, and nobody independently
verified them. Only Wave-3 attestations are issuer-committed — and only
after a real issuer ceremony with a real issuer, which has not happened in
this run.

## 4. The new attest/proveAttested circuits are UNDEPLOYED in this run

The new `attest` / `proveAttested` circuits perform no chain writes in this
run. Any counters, tallies, or dashboard figures shown for them are labeled
**not-deployed** — they are aspirational UI, not on-chain evidence.

## 5. GeroWallet's default cloud proving sends witnesses to Gero infra

The default wallet path is GeroWallet, whose default proof location is Gero
Cloud: witness data used to build a proof is sent to infrastructure operated
by Gero (see `docs/wallet-trust.md`). That is a real trust boundary for
clinical data. Local proving is available as an option; it is not the
default.

## 6. The Supabase trial catalog is non-proof public data

If a Supabase catalog is present, it is plain public data about trial
listings — it is **not** part of any proof. A poisoned or tampered catalog
cannot forge a proof: proofs depend only on committed attributes and
issuer-signed attestations, neither of which the catalog can supply.

## 7. Synthetic data only — no real patient records anywhere

Every patient record in this repository — FHIR bundles, judge credentials,
attestations — is synthetic. There are no real patient records anywhere in
this project.
